# Frontend организуется по FEOD

Владелец выбрал FEOD для frontend с базовыми слоями `app/pages/modules/common/global`; backend организуется отдельно и не обязан повторять эти слои. Выбор устанавливает единые границы модулей до появления кода, ценой явных правил импортов и публичных API вместо произвольной структуры по техническим типам файлов.

Предметная логика находится в модулях; `pages` содержат тонкие страницы, `app` — сборку приложения, маршрутизацию и интеграции. Между модулями используется публичный API через `index.ts`; импорт внутренностей другого модуля запрещён. `common` содержит небольшие повторно используемые элементы, а не самостоятельную предметную модель; `global` не является обычным импортируемым модулем. Эти правила опираются на установленный навык, а не на Feature-Sliced Design.

Установлен проектный навык `.agents/skills/feod` из [Sdju/feod](https://github.com/Sdju/feod/tree/54a39cd4a44fbd01620ac58a0367cc45af77c895/skills/feod). Версия и лицензия записаны в `.agents/feod-skill.json` и `.agents/feod.LICENSE`. Точные пути frontend, профиль `feod.profile.md`, способ связывания TanStack Router со страницами и настройки линтера нужно определить при создании структуры проекта; эта запись не утверждает ещё не созданный профиль.
