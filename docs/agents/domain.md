# Domain Docs

Use a single-context layout for this repo.

## Before exploring

- Read root `GLOSSARY.md`, if it exists.
- Read decisions under `docs/adr/` that concern the area being explored.
- If these files do not exist, proceed silently. The `domain-modeling` skill creates them when terms or decisions are resolved.

## Use the glossary's vocabulary

Use the terms defined in `GLOSSARY.md` when naming domain concepts in code, issues, hypotheses, and tests. Record meaningful vocabulary gaps for `domain-modeling`.

## Surface ADR conflicts

Explicitly identify an existing ADR before proposing a contradictory decision, and explain why it should be reconsidered.
